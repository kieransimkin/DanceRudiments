# Low-poly mesh dance demos

The `meshes/` gallery presents two original skinned characters driven by real
captured dance recordings. It uses DanceRudiments' existing native recording
sampler, numbered skeletal channels and optional package loader. The gallery
is built separately from the default pattern catalogue and base npm/Python
packages.

| Character | Captured motion | Full source duration | Mesh |
| --- | --- | --- | --- |
| **Boxbot** | CMU `60_01`, salsa | About 37.37 seconds, 2,243 source frames at 60 fps | Angular robot, 2,160 weighted vertices. |
| **Prism** | CMU `05_18`, dance including arabesques, turning jumps and back bends | About 15.24 seconds, 1,830 source frames at approximately 120 fps | Faceted dancer, 2,850 weighted vertices. |

Both meshes contain 31 source joints and vertices blended between neighboring
bones. Their geometry is generated by the project's own Three.js character
code. The source poses, movement, timing and root translations come from the
pinned motion captures. The full source actions, including their calibration
first frame, are retained.

## Use the gallery

Choose a character, then press **Load & play**. Initial navigation loads the
interface and renderer; the selected rig, package, profile, recording and WASM
are requested only after that explicit load. Choosing the other character
unloads the previous skin, recording cache and native handle. **Unload** releases
them without loading another character.

The transport supports play/pause, restart, integer-pip seeking and preview
speed. Playback stops at the final recorded pip. Camera orbit/zoom and reset
change the view, while the camera follows the captured root translation. A
reduced-motion preference leaves a newly loaded character paused. Desktop and
mobile layouts share the same native playback.

The clips have **time-only timing**: one second maps to one nominal beat and
64 native pips. Their musical BPM and downbeat phase have not been annotated or
verified. Preview speed changes elapsed playback speed; it does not establish
musical beat matching. No music is bundled. To align a recording to a song,
provide source beat anchors and a target clock through the offline
[rig-motion compiler](rig-motion.md).

## Skeleton and playback contract

Each dance uses its exact source skeleton profile: 31 joints, 127 numbered
channels, saved rest transforms, a stable type URI and a profile fingerprint.
These are source-skeleton recordings; Rigify retargeting is a separate explicit
operation. The browser applies complete WXYZ quaternion groups and root
translation in source space, then transforms the presentation group for the
Three.js view. Styling, floor placement and camera framing do not alter the
recording or its source profile.

The production TypeScript motion-package loader checks the manifest, expected
profile, compressed byte count and hashes before constructing the existing
native WASM recording handle. A scene holds only its current motion chunk; the
transport requests absolute integer pips. JavaScript handles loading, clock
position, decoded channel application and rendering. Native recording sampling
remains shared with the Python/C++ implementation.

## Rebuild just the gallery

The asset builder needs the native Python extension and the optional
`motion-import` NumPy extra. The frontend builder needs the lockfile's exact
Three.js and esbuild versions. Blender and the bulk optional motion collections
are not required.

Run the temporary-directory preflight required by
[AGENTS.md](../AGENTS.md), then:

```sh
python -m pip install '.[motion-import]'
npm ci
python tools/build_mesh_demo_assets.py --output-dir generated/mesh-demo-assets --cache-root .cache/motion-sources/cmu-dance --download
node tools/build_mesh_demo.mjs --assets-dir generated/mesh-demo-assets --output-dir dist/pages/meshes
python -m http.server 8000 --directory dist/pages
```

Open `http://localhost:8000/meshes/`. The builder defaults to the checkout's
package version and complete Git commit; `--version` and `--commit` may supply
the validated release identity explicitly.

`--download` authorizes only the two URLs pinned in
[`tools/mesh_demo_sources.json`](../tools/mesh_demo_sources.json). The source
files total about 3.1 MB and are checked for exact size and SHA-256 before
conversion. Without `--download`, the asset builder requires those verified
files already in its local cache. Use a fresh asset output directory; source
archives and generated motions stay out of the base packages and default
catalogue. The frontend builder can replace its own previously generated
output tree and removes stale files as part of that bounded rebuild.

The source asset directory contains `catalogue.json`, two scoped motion
packages, source rigs, notices and independent browser references. The final
HTTP route adds locally bundled Three.js, the production package loader,
`recording.wasm`, `build.json` and the UI. It has no runtime CDN dependencies.

## Reproduce the browser checks

```sh
python -m pip install playwright==1.64.0
python -m playwright install chromium
npm test
python -m unittest discover -s tests/python -p test_mesh_demo_assets.py -v
python -m unittest discover -s tests/python -p test_release_pages.py -v
python tools/test_mesh_demo_browser.py --site-dir dist/pages --output-dir dist/mesh-qa --gallery-only
```

The browser tool starts its own loopback HTTP server. `--chromium /path/to/chromium`
selects an existing matching browser; otherwise it uses Playwright's installed
Chromium. Software WebGL through ANGLE/SwiftShader is supported for headless CI.
It saves a JSON receipt and one desktop/mobile PNG per character.

For each dance, four reference pips cover the first frame, an early moving
frame, the middle and the last sample. The tool compares every native normalized
channel with separately decoded package bytes, every physical channel with the
Python-native player, and all 31 joint world matrices with independently
composed NumPy transforms. It also checks actual skinned vertex movement,
playback controls, lazy fetches, disposal, layout and unhandled browser errors.
The browser never fetches the reference files for playback.

A `--gallery-only` run reports exactly that scope. It is useful when developing
the meshes without rebuilding the large catalogue snapshot, but cannot seal a
release site. The complete release path first renders and tests the existing
native visualizer, prepares its navigation link, then runs this tool without
`--gallery-only` against the combined site. See the
[release guide](release-demo.md) for exact assembly, attachment and deployment
commands.

## Sources and rights

The captures originate in the [CMU Graphics Lab Motion Capture Database](http://mocap.cs.cmu.edu/),
with [subject 60](http://mocap.cs.cmu.edu/search.php?subjectnumber=60) and
[subject 5](http://mocap.cs.cmu.edu/search.php?subjectnumber=5) identifying the
performances. The pinned BVH conversion is Bruce Hahne's cgspeed distribution,
retrieved through the exact mirror commit recorded in the source plan. The
converter's 60 fps correction for the salsa take is explicit in its provenance.
The approximately 120 fps value for the second take follows its saved BVH frame
time. Both retain documented units, axes and source hashes.

The motion data carries CMU's custom terms: it may be copied, modified and used
in commercial projects, with direct resale of the motion data prohibited.
It is not relabeled as CC0 or CC BY. Each generated package and downloadable
mesh bundle includes the source terms, CMU/NSF attribution, converter credit,
source URLs, hashes and conversion choices. Original character geometry and
runtime dependencies retain their own project/dependency notices. Consult the
bundled `LICENSE.txt`, `THIRD_PARTY_NOTICES.md` and `SOURCES.json` for the full
source-specific record.

## Release and deployment

The [Release demo workflow](../.github/workflows/demo-release.yml) builds this
gallery from the same exact tag as the root pattern viewer. The
`DanceRudiments-pages-vX.Y.Z.zip` download contains the complete site; the
separate `DanceRudiments-mesh-demos-vX.Y.Z.zip` contains the `meshes/` route.

Pages deployment uses the repository's existing enablement variable and
environment approvals. Only the latest stable release can publish the site;
older-tag rebuilds keep their release downloads without replacing the latest
Pages content. The post-deployment verifier checks both routes and every public
asset against the tested version/commit manifest.

Earlier API/package changes did not add a visible mesh renderer. A green
main-branch check or a successful deployment of the older pattern visualizer
therefore does not establish that this gallery was deployed. The mesh page
requires a fresh release containing these builders; pre-gallery tags such as
`v0.3.0` cannot acquire the new code through a manual rerun.
